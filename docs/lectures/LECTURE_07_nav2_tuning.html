Nav2 tuning: smooth, reliable motion

Learning goal. Understand the knobs that turn "it reaches the goal but pivots/jerks" into "it glides": inflation (inflation_radius, cost_scaling_factor), the DWB critics and trajectory sampling, recovery behaviors, and the optional smoothers. By the end you can read a behavior symptom and know which knob to turn. Study this before touching params.

1. The tuning mindset

Concept

Default params get you "it moves". Tuning matches the params to YOUR robot and space: a small diff-drive bot in a 5×4.9 m room needs different values than a warehouse robot. The discipline: change one knob, observe in RViz (costmap + path + trajectory), repeat. Never five at once.

2. Inflation: the most impactful knob in a small room

Concept

The inflation layer spreads cost outward from every obstacle so the planner keeps clearance. inflation_radius = how far the halo extends; cost_scaling_factor = how steeply cost decays within it (exponential: higher = faster drop-off).

Trap — the small-room killer

Humble's default inflation_radius: 0.55 literally walls off a small room: halos from opposite walls overlap, leaving no zero-cost path → "No valid path" with the costmap fully colored. cargo_bot uses 0.35. Too low instead → the robot cuts corners and clips walls.

3. DWB: trajectory sampling and critics

Concept

DWB (20×/s) samples candidate trajectories and scores them with critics.

Sampling (the search space): vx_samples/vtheta_samples (how many velocities to try), max_vel_x (0.26 — small robot), max_vel_y: 0.0 (diff-drive cannot strafe), accel limits, and sim_time (1.7 s — how far each candidate is rolled out; too short = short-sighted, too long = sluggish).

Deeper — critics (where pivoting/jerk lives)

Each critic scores a trajectory; the weighted sum picks the winner:

  • PathAlign / PathDist — reward following the global path. Raising PathAlign.scale reduces pivoting/wandering.
  • GoalAlign / GoalDist — reward progressing to the goal.
  • RotateToGoal — the final in-place rotation to the goal heading.
  • Oscillation — penalizes flip-flopping (prevents wiggling stuck).
  • BaseObstacle — penalizes trajectories near obstacles.

Symptom → knob: pivots/won't commit → raise PathAlign.scale; wiggles in place → Oscillation + goal tolerances; jerky → sampling granularity + smoothers (§5).

4. Goal tolerances and the progress checker

Concept

xy_goal_tolerance/yaw_goal_tolerance (0.25) = how close counts as "arrived" (too tight → a small robot oscillates forever; too loose → stops short). The progress_checker (required_movement_radius, movement_time_allowance) declares "stuck" if the robot does not move 0.5 m in 10 s → triggers recovery. Tune so normal slow maneuvers do not falsely trip it.

5. Recovery behaviors and smoothers (Step 2, optional)

Concept

Recoveries (spin / backup / wait) run when stuck — mostly tune so they do not fire too eagerly (false stuck) and the distances suit the room.

Smoothers (only if motion is still rough): smoother_server (simple_smoother) smooths the global path (rounds NavFn's sharp corners — biggest win for pivot-at-every-corner); velocity_smoother smooths the velocity commands (limits jerk/accel — biggest win for abrupt start/stop).

In cargo_bot

Project rule: only add smoothers if Step 1 motion bothers you. Do not pre-optimize. See FASE4_GUIA_NAV2.md section 7.

6. A tuning workflow for cargo_bot (4a.2)

In cargo_bot
  1. Send goals, watch RViz: pivot? jerk? cut corners? refuse to plan?
  2. "No valid path" / costmap fully colored → lower inflation_radius (at 0.35).
  3. Pivots / wanders off path → raise PathAlign.scale, check sim_time.
  4. Jerky → add smoother_server; abrupt start/stop → add velocity_smoother.
  5. Re-test with several goals + the waypoint_follower.
  6. When it glides, leave the scene ready to record the clip.
